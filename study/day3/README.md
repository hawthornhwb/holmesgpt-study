## 1 从接入需求理解为什么要插件化

沿用已有 [09_crashpod](../../tests/llm/fixtures/test_ask_holmes/09_crashpod/test_case.yaml)。用户只问 `payment-processing-worker` 有什么问题。调查需要把服务名变成准确的 namespace 和 Pod 名，再读当前与上一次容器日志，结合配置确认 `DEPLOY_ENV` 缺失。本页推演合理的调查路径，本次未运行这条 eval。

具体的两种能力是：`kubernetes/core` 中的 YAML 工具 `kubernetes_jq_query` 查询资源；`kubernetes/logs` 中默认的 Python 工具 `fetch_pod_logs` 读取日志。先理解它们怎样进入同一个调用框架，再讨论增加日志平台时怎样复用。

如果每接一个数据源都直接给调查主循环增加一段平台专用逻辑，主循环就要了解不同 API 的认证、参数、返回格式和错误处理。扩展数据源时，这些职责会一起增长。

插件化把职责分开：具体工具负责访问数据源；框架负责加载与管理工具、向模型提供描述、查找实现并统一调用。模型根据问题和已有证据提出工具调用请求。

用自己的话写 3 句：调查需要哪些外部能力？增加平台时会遇到什么维护问题？工具模块与框架分别承担什么工作？能回答这三句，就知道今天的设计在解决什么问题。

## 2 理解四个部分的职责

| 部分 | 负责什么 | 日志查询例子 |
| --- | --- | --- |
| **Tool** | 一个可执行的具体操作，具有名称、说明、参数和返回结果 | `fetch_pod_logs` 读取指定 Pod 的日志 |
| **Toolset** | 组织相关工具，管理共同配置、启用状态与前置条件 | `kubernetes/logs` 管理日志能力并检查 kubectl 是否可用 |
| **Schema** | 向模型描述工具名称、用途和参数规范 | 日志工具要求准确的 `pod_name`、`namespace`，可带时间、过滤和 `limit` |
| **执行实现** | 实际访问数据源，处理业务参数与底层错误 | Python 日志实现构造 kubectl 参数数组，读取并处理当前和上一次日志 |

这四项是职责划分。Schema 是工具对模型的描述，具体查询由执行实现完成。HolmesGPT 可以通过 YAML 命令工具、Python 工具等方式实现不同操作。

用仓库里的实际工具描述一次输入输出：

```text
名称：fetch_pod_logs
用途：查询准确 Pod 的日志，用于检查启动报错。
必填参数：namespace、pod_name。
可选参数：start_time、end_time、filter、exclude_filter、limit。
本例输入：namespace=app-09，pod_name=资源查询返回的准确名称，limit=100。
要发现的证据：Environment variable DEPLOY_ENV is undefined。
返回：处理后的日志、查询与过滤信息；底层读取错误按实际结果返回。
```

想一想：为什么先查资源，不能把 Deployment 名直接传给日志工具？为什么说明要写“准确 Pod 名”？时间、过滤和 limit 怎样帮助后续查询？日志平台的连接地址、认证等共同配置适合放在哪里？

参考思路：Deployment 名与 Pod 名不同，必须先发现对象；描述与 Schema 帮助选择和填写参数。同一接口可以封装 YAML 和 Python 实现，但业务语义与错误处理仍需各实现负责。仅检查 kubectl 客户端可用，也不能证明实际有权限读取目标日志。

## 3 用一个工具讲清接入 调用与失败

先看这条路径，再用日志工具复述：

```text
加载 kubernetes/core 的 YAML 定义、kubernetes/logs 的 Python 工具及配置
→ 框架加载工具集，形成可用工具并按名称管理
→ 把名称、说明和参数 Schema 提供给模型
→ 模型提出资源查询，取得 namespace、准确 Pod 名和容器状态
→ 模型提出 fetch_pod_logs、具体参数与调用 ID
→ 程序查找工具，执行具体查询
→ 结果或错误关联调用 ID，进入后续调查
```

前半段解释“工具如何进入框架”，后半段解释“一个工具怎样被调用”。你已掌握后半段，今天重点补齐前半段的职责与理由。

再讨论三个情况：

- **模型给错参数。** 把 `payment-processing-worker` 当准确 Pod 名，可能得到 NotFound；先重新发现对象。Schema 帮助生成参数；**当前通用类型转换不是完整的 JSON Schema 校验**，日志实现还有必填字段提取和 Pydantic 参数对象，业务范围仍需具体检查。
- **查询权限不足。** 保留实际查询对象与底层 Forbidden 等错误，供后续调查使用。健康检查通过不能解决 RBAC；模型能否纠正取决于已有权限与其他可用查询路径。
- **查询没有日志。** 查看 Pod、namespace、时间与过滤范围，以及当前/上一次日志读取错误。没有查到 `DEPLOY_ENV` 错误本身不能证明变量已正确配置。

至少讲出两个取舍：统一接口降低接入成本，但不能消除平台差异；工具说明有助于选择，但提供大量工具 Schema 也占用上下文。工具数量多本身不能证明诊断质量高。

## 4 面试讲述与核心追问

先借助骨架讲一遍，再合上文档，用自己的话讲第二遍。参考段落介绍框架机制，个人工作在文末按实际经历填写。

> 在支付处理服务重启这个 case 里，Agent 先查询资源发现准确的 Pod，再读取日志。资源查询是 YAML 工具，当前日志查询是 Python 工具，但都通过 Tool 接口提供名称、用途和参数 Schema；Toolset 负责组织能力和管理配置与前置条件。模型提出调用后，执行器按名称找到对象并执行，返回结果或错误。因此接入新的日志平台时，可以复用调查循环，具体实现仍需处理平台认证、过滤与错误。设计难点在于统一接口之外保留业务语义：例如服务名不能直接作为 Pod 名，kubectl 可用不代表有日志权限，Schema 也不等于完整业务校验。

每个追问先回答 30–60 秒，卡住后只补当前问题。

| 核心追问 | 回答需要包含什么 |
| --- | --- |
| 为什么需要工具插件化？ | 多数据源接入需求；框架与数据访问职责分开；扩展时复用调查逻辑 |
| Tool、Toolset、Schema 分别负责什么？ | 一个操作、一组工具及共同管理、面向模型的能力描述 |
| 这个 case 怎样用到统一接口？ | 资源查询是 YAML，日志查询是 Python；共同提供 Schema 和 invoke；先发现准确 Pod |
| 模型怎么知道用哪个工具，程序怎么找到实现？ | 模型依据描述和上下文选择；程序按名称查找；调用 ID 关联结果 |
| 参数错误、无数据、权限不足分别怎么办？ | 参数处理与业务校验；无数据说明查询范围；底层错误提供给后续调查 |

答顺以后，再补两个深入问题：为什么统一接口仍需要各工具做业务校验？工具多了会带来哪些选择和上下文成本？

简历里的“约 50 个工具集、250 个工具能力”涉及版本和统计口径。先讲清设计，数字以实际核对为准；可用工具还受启用配置与前置条件影响。

| 当前疑问 | 查哪一小段 | 查到什么即可停止 |
| --- | --- | --- |
| 本例两个工具怎样定义？ | [kubernetes.yaml](../../holmes/plugins/toolsets/kubernetes.yaml) 的 kubernetes_jq_query；[logging_api.py](../../holmes/plugins/toolsets/logging_utils/logging_api.py) 的 PodLoggingTool | 一个 YAML script，一个 Python Tool；名称和参数各在哪里 |
| 模型能看到具体 command 吗？ | [tools.py](../../holmes/core/tools.py) 的 get_openai_format() | 确认提供名称、说明和参数，command 与 user_description 不在这里传入 |
| 程序怎样按名称找到工具？ | [tool_executor.py](../../holmes/core/tools_utils/tool_executor.py) 的 get_tool_by_name() | 看懂工具名如何找到对象 |
| 通用调用与具体操作怎样分工？ | tools.py 的 invoke() | 看懂它调用 _invoke()，并处理通用调用流程 |

参数转换细节属于深入查证：**定义对象的 Pydantic 校验、模型参数 Schema、保守类型转换、具体业务校验是不同层次。** 当前转换路径中，缺失字段会跳过，未知字段保留，enum、范围与嵌套结构没有在这一步统一校验。原先强调的这些边界继续保留，但今天无需逐行研究转换函数。

如果一个问题确实需要实验支撑，可选择 [本地工具接入实验](tool-lab.md) 的离线部分，或阅读现有 [Schema 测试](../../tests/test_openai_formatting.py) 的一条相关断言。实验结果记录在本页，是否运行由当前疑问决定。
